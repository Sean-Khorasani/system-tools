# wintcp Assembly-Replacement Candidates

30 candidates found by deep analysis of `wintcp/src` (2026-10-09), ranked by
expected ROI. Every `file:line` below was verified against the tree. The 7
shipped `*Opt` functions are excluded. Procedure per candidate is the same as
the first round: copy the original into `bench/orig_functions.cpp`, comment it
out in `bench/replaced_functions.cpp`, implement the `*Opt` in
`opt_functions.cpp` behind `bench/asm_functions.cpp`, gate with
`testAssemblies` + `bench_orig`/`bench_asm` + `run_benchmark_report.py`.

Conventions: SSE2 is x64 baseline (no gating). SSE4.2/AVX2/BMI2 need runtime
`__cpuid` gating with scalar fallback. Untrusted-input bounds checks always
stay in C++; only the compute after the check is replaced.

## Deliberately NOT recommended

- `DnsResolver.cpp:38-128` (`DoLookup`/`Offer`): `InetPtonW`+`GetNameInfoW` RTT dominates; hashing is noise.
- `BlockConn.cpp:134-247` (`IsAllZero`/`FormatAddressHex`/`FormatAddress`), `:1076-1132` ledger scan: per-click/per-read cold paths.
- `ProcessInfo.cpp:256-497` (`ResolveOne`/`Batch`): `OpenProcess`/`QueryFullProcessImageNameW` syscalls dominate; PID batching already done.
- `Alerts.cpp:142-266` (`Evaluate`): single linear scalar pass, memory-bound, nothing to vectorize.
- No wildcard/glob engine exists (filter text match is substring-only) - that would be a feature, not an optimization.
